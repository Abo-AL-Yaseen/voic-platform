# إدارة المحتوى والوسائط

Current operational commands, seven-migration state, shared production limits and separate runtime/migration grants are in [operations](operations.md). Older phase-specific migration/apply commands below are historical; do not rerun them against the current development database. Use [combined manual acceptance](manual-acceptance.md) for current role/MFA journeys.

Current staff authentication/permissions are superseded by the implemented [staff security and administration guide](staff-security.md). Mandatory MFA now protects every staff endpoint; employee and audit workspaces are connected. Production business writes remain disabled pending explicit operational approval. Earlier phase verification below is historical.

اعتمد تنفيذ هذه المرحلة بطلب صريح بعد مساحة المبيعات (`6e92fa2`). تستخدم NestJS وTypeORM
وMySQL Server المحلي، وReact وTanStack Query. لا Docker ولا نشر. العربية RTL والإنجليزية
LTR فقط. بقاء النص في المصدر أو استيراده محليًا لا يعني اعتماده للإنتاج.

## الصلاحيات ودورة العمل

| الإجراء | مدير | محرر محتوى | مبيعات/عميل/زائر |
| --- | --- | --- | --- |
| قراءة المسودات/المكتبة والمعاينة | نعم | نعم | ممنوع |
| إنشاء/حفظ/طلب مراجعة/رفع وسائط | نعم | نعم | ممنوع |
| اعتماد ونشر/إلغاء نشر/أرشفة المحتوى | نعم | لا | ممنوع |

تتطلب الكتابة بريدًا موثقًا وجلسة حقيقية وCSRF وأصلًا مسموحًا، مع إعادة فحص الدور داخل
المعاملة، وحدود للطلبات. تتبع بوابة الموظفين الحالية: `STAFF_INQUIRY_WRITES=true` مع
`MAIL_MODE=capture` في التطوير/الاختبار فقط، ولا يتجاوز هذا الإعداد MFA الإلزامي وصلاحيات
الموظف الحالية. في الإنتاج تبقى الكتابة معطلة حتى اعتماد تشغيلي صريح؛ الإعداد المحلي مرفوض
في الإنتاج. إدارة الموظفين وسجل التدقيق متصلان وفق دليل أمان الموظفين؛ دليل العملاء المستقل
للموظفين غير متصل بعد. الاختبارات المحلية لا تمثل شهادة أمن إنتاجية.

الحفظ ينشئ مراجعة ثابتة جديدة ولا يغير النسخة العامة. طلب المراجعة مرتبط بمراجعة محددة؛
أي حفظ لاحق يبطل الطلب. المدير يراجع المعاينة ثم يؤكد نشر تلك المراجعة. يقتضي النشر اكتمال
الحقول المطلوبة باللغتين وصلاحية العلاقات والوسائط. النشر المحلي الافتراضي `development`.
الاعتماد للإنتاج قرار منفصل صريح: `approveForProduction:true` و
`confirmation:"APPROVE BOTH LOCALES"`، وللخصوصية أيضًا `legalApproval:"LEGAL REVIEW COMPLETE"`.
يسجل الخادم الفاعل والمراجعة. لا يمنح الاستيراد اعتمادًا أو فاعل اعتماد تلقائيًا.

كل كتابة تحمل UUID v4 في `key` ونسخة `version` الحالية، مع `action`؛ الإنشاء يستخدم
`action:"create"` و`body` و`version:0`. الحفظ يستخدم `action:"save"` و`body`، والإجراءات
الأخرى `review|publish|unpublish|archive`. إعادة المفتاح مع المدخل نفسه لا تكرر الكتابة وتعيد السجل الحالي؛ تغييره
لمدخل مختلف أو الكتابة على نسخة قديمة تعيد 409. تحتفظ الواجهة بالمدخلات عند التعارض، وتعرض
المراجعة الجديدة للمقارنة والاستبدال الصريح. لا تحفظ المسودات أو رموز الجلسة في browser storage.

## المخطط والحفاظ على البيانات

الهجرة الخامسة `ContentWorkspace1795532400000` تضيف ستة جداول InnoDB/utf8mb4 فقط:

- `content_documents`: هوية النوع/المعرف/slug، النسخة ومؤشرات المسودة والمراجعة والمنشور
  والاعتماد والأرشفة؛ uniqueness للمعرف والـslug داخل النوع.
- `content_revisions`: أجسام JSON ثابتة مرقمة مع الفاعل والتاريخ.
- `content_media` و`content_media_usage`: سجل الأصل/الرفع والنص البديل، ومراجع كل المراجعات المحتفظ بها.
- `staff_editorial_events`: سجل إجراءات بفاعل ودور ونسخة ومفتاح منع تكرار وبصمة؛ بلا أجسام محتوى أو أسرار.
- `content_write_lock`: قفل معاملة يمنع سباقات النشر والعلاقات والوسائط.

إجمالي الكيانات 21 والهجرات خمس. `synchronize`, `dropSchema`, `migrationsRun` تبقى false.
النشر وحده يحدث إسقاط جداول الكتالوج الأصلية في المعاملة نفسها؛ لا يغير ملاحظات البحث
الخاصة. المعرفات والـslugs الموجودة ثابتة. لا حذف مدمر للمنتجات أو التصنيفات أو الاستخدامات.
منع حذف عبوة موجودة، ويمكن إيقاف نشرها؛ لقطات الاستفسارات القديمة تبقى ثابتة. تمنع المراجع
الموجودة في الكتالوج أو أي مراجعة محتفظ بها إلغاء نشر/أرشفة تصنيف أو استخدام متعلق بها.
الراجع `down` يرفض قاعدة تحتوي مستندات أو وسائط أو أحداثًا؛ اختباره المدمر محصور بقاعدة مؤقتة.

الاستيراد صريح وinsert-only: يلتقط الكتالوج الموجود، ويسجل مراجع الأصول دون نسخها، وينقل
الوصفات الأربع من `backend/data/recipes-baseline.json` وسبع سجلات صفحات من
`backend/data/pages-baseline.json`. تكراره يتخطى المستندات والوسائط الموجودة بالكامل، بما
فيها النصوص البديلة والاعتمادات والأرشفة؛ لا يعيد ضبط التحرير أو ترتيب الرئيسية.

## العقود والواجهة

كل المسارات أدناه تبدأ بـ`/api/v1`:

| المسار | الوظيفة |
| --- | --- |
| GET `/staff/content/metadata` | العلامات المتاحة وصلاحيات الجلسة |
| GET `/staff/content/:kind` | قائمة خاصة؛ `products,categories,uses,recipes,pages` |
| GET `/staff/content/:kind/:id` | المسودة والمنشور ومؤشرات النسخ والصلاحيات |
| POST `/staff/content/:kind/:id/actions` | إنشاء/حفظ/مراجعة/نشر/إلغاء نشر/أرشفة |
| GET `/staff/content/media` | مكتبة الوسائط |
| GET `/staff/content/media/:id/usage` | مراجع المراجعات المحتفظ بها |
| GET `/staff/content/media/:id/preview` | صورة رفع خاصة بالموظفين |
| POST `/staff/content/media/upload` | JSON: `key,filename,data` (base64), `altAr,altEn` |
| POST `/staff/content/media/:id/actions` | `key,version,action`؛ تحرير alt أو أرشفة أو حذف رفع غير مستخدم |
| GET `/recipes` | وصفات منشورة؛ `lang,q,category,productId,page,pageSize` |
| GET `/recipes/:id` | وصفة منشورة، `lang` فقط |
| GET `/content/:id` | سجل صفحة منشور، `lang` فقط |
| GET `/media/:file` | رفع مستخدم في مراجعة منشورة مسموحة فقط |

القوائم الخاصة تقبل `q,status,page,pageSize` فقط؛ `page` من 1 إلى 10000، والحجم 1–50،
والرد `{items,total,page,pageSize,totalPages}`. البحث الخاص عن المعرف/slug، وبحث المكتبة
يشمل alt والمعرف. حالات المحتوى `draft,review,published,archived`؛ القيمة الفارغة لجميع الحالات. انظر التحقق الفعلي
في `ContentService.filters/list` عند إضافة مستهلك. معرف وصفة التفاصيل هو slug المحفوظ.
حد JSON للمحتوى 60,000 بايت. لا حقول عامة للفاعل أو المراجعات الخاصة أو البحث الداخلي.
الأخطاء آمنة: 400 للحقول، 401 للجلسة، 403 للصلاحية/CSRF، 404 لغير المنشور، 409
للتعارض/المراجع/المراجعة المطلوبة، و429 للحدود. لا تنشر الواجهة نص خطأ SQL.

تفاصيل الأجسام المرجعية في `backend/src/content/content.validation.ts` وأنواع الواجهة
في `frontend/src/services/editorial.ts`. المنتج يحفظ الاسم والوصف العربي/الإنجليزي، المكونات
اختيارية واعتمادها منفصل، معرف العلامة/التصنيف/الاستخدامات، الصورة، ترتيب العرض، والعبوات
بمقدار نصي ووحدة `g|kg|L` أو null/null للمجهول. مفاتيح أحجام الأصل تحفظ الكسور و`L`.
الوصفة تحفظ العناوين والوصف والمكونات ومقاديرها الاختيارية والخطوات المرتبة وروابط المنتجات؛
المقدار المفقود لا يتحول إلى صفر. لا حقول مخترعة للتغذية أو المؤلف أو الحصص.

سجلات الصفحات `home,about,business,contact,shared,header,privacy` تحتوي `texts` ثنائية اللغة،
و`images,links,rows,featuredProductIds`. مفاتيح البنية وترتيب أقسامها ثابتة، وليست HTML أو
JavaScript. `shared` هو مصدر الهاتف/الفاكس/البريد/العنوان/الروابط المشترك. أسماء عناصر النظام
والأزرار تبقى في كود الواجهة. الروابط الخارجية HTTPS فقط؛ لا userinfo، والبريد والهاتف
متحققان. الخصوصية تحتفظ بتنبيه مراجعة بشرية واضح.

Services تملك HTTP، وhooks المحتوى/التحرير تملك المفاتيح والاستعلامات والتحويرات. بيانات
التحرير خاصة ومقيدة بالهوية والدور وعهدة الجلسة مع إلغاء الاستجابة المتأخرة. لا تخمين لعضوية
القوائم أو أعدادها. النشر يبطل عائلات المنتجات/المحتوى المتأثرة ويرسل BroadcastChannel؛
المشاهد الأخرى تعيد الجلب عند التركيز وكل 30 ثانية. لا حاجة للخروج والدخول. البيانات العامة
من مراجعة منشورة متسقة؛ فشل API يظهر إعادة محاولة ولا يستدعي بيانات الوصفات المحلية.

## الوسائط والتخزين

`LocalMediaStorage` يخزن افتراضيًا في `backend/.local-data/media/` خارج build، وهو ignored.
الاسم UUID.webp مولد بالخادم. PNG/JPEG/WebP فقط، بحد 5 MiB و6000 بكسل للضلع و24 مليون
بكسل، وصورتين متزامنتين لكل العملية. يتحقق التوقيع ثم يفك الترميز فعليًا بـsharp، يرفض
الصور المتحركة والتالفة، ويعيد ترميز WebP مع إزالة metadata. SVG المرفوع والمسارات التنفيذية
وtraversal مرفوضة؛ الأصل SVG المسجل يبقى الأصل الموجود. لا جلب عنوان بعيد.

الرفع 20 محاولة/15 دقيقة، وكتابات التحرير 60/15 دقيقة بالإضافة لحدود الجلسة. الأصل المسجل
لا يحذف من القرص. أي مراجعة محتفظ بها أو لقطة استفسار تمنع حذف/أرشفة وسيط مرتبط بها.
الصور غير المنشورة لا تخدم علنًا، ومعاينتها تتطلب جلسة الموظف. الصورة المفقودة لـSun Gold
تبقى مفقودة إلى أن يختار المحرر أصلًا فعليًا ويعتمده المدير.

صور API تستخدم CORS صريحًا من الواجهة: `anonymous` للمنشور و`use-credentials` للمعاينة
الخاصة، مع قائمة CORS الحالية للأصول المسموحة. تبقى ترويسة CORP الافتراضية للخادم؛ لا
يُفتح تضمين الصور الخاصة لطلبات `no-cors` من مواقع أخرى. راجع
[شرح CORP الرسمي](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cross-Origin-Resource-Policy)
و[عقد CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) عند تغيير أصل الاستضافة.

فشل معاملة الرفع يحذف الملف الذي أنشأته فقط. سجل ملكية خاص `.owned-*.json` يساعد تنظيف
الأيتام بعد تعطل العملية. `node scripts/cleanup-local-media.mjs` يعرض عدد الملفات المؤهلة
دون حذف؛ `--apply` يحذف فقط UUID مملوكًا ثبت أنه غير مسجل، أقدم من 24 ساعة، داخل المجلد
الحقيقي المحدد. لا يحذف مجهول الملكية ولا يتبع symlink ولا يفحص الأصول الأصلية للحذف.

النسخة الاحتياطية يجب أن تضم MySQL ومجلد `.local-data/media` معًا في نقطة متسقة وبصلاحيات
مقيدة؛ استعادة قاعدة دون ملفاتها تفقد الصور المرفوعة. لم يختبر نسخ/استرجاع إنتاجي هنا.
قبل الإنتاج يلزم محول تخزين دائم مشترك، وسياسة نسخ/استرجاع ومراقبة وحدود موزعة ومراجعة أمنية؛
القرص المحلي الحالي مخصص للتطوير، ولا يوضع خلف build مؤقت. لا تلتزم بالرفع أو البريد الملتقط.

## أوامر الإعداد والتحقق

من `backend/` مع `.env` المحلي ignored، دون عرض كلمات المرور:

```powershell
pnpm.cmd build --outDir .tmp/content-build
pnpm.cmd migration:show
pnpm.cmd migration:run
$env:CONFIRM_DEVELOPMENT_CONTENT = 'yes'
try { node scripts/import-development-content.mjs } finally { Remove-Item Env:CONFIRM_DEVELOPMENT_CONTENT }
pnpm.cmd db:check
```

لا تشغل هجرة قبل فحص البيانات الموجودة والنسخة الاحتياطية. أداة تطبيق هذه المهمة
`node scripts/apply-native-content.mjs` أضيق: تتحقق من أدلة الاختبار الثلاثة، وتقبل فقط
القاعدة المحلية المعروفة وتسلسل الهجرات المتوقع، وتطبق الهجرة الإضافية والاستيراد، وتقارن
بصمات الجداول الخمسة عشر القديمة قبل/بعد، ثم تفحص readiness و11 منتجًا و4 وصفات و7 صفحات
بخادم مؤقت. لا تستبدل خوادم المستخدم ولا تعيد ضبط القاعدة.

اختبارات MySQL المدمرة تكون فقط على قاعدة عشوائية مؤقتة يملكها المشغل:

```powershell
node scripts/setup-native-mysql.mjs --content-test
```

أدخل كلمة مرور مسؤول MySQL في الطرفية المخفية فقط. في Git Bash أضف `winpty` قبل `node`.
عند رسالة `Auth test operator ready` أبق الطرفية مفتوحة. إشارات `.tmp` الآمنة تسمح بتكرار
نطاقات `content,staff,regression` دون حفظ اعتماد المسؤول؛ `finish` ينهي المشغل ويحذف فقط
قاعدته ومستخدمه المؤقتين. الاختبار يستخدم `.tmp/auth-build` وملفات وسائط خاصة به وواجهة
127.0.0.1:8444 وAPI بمنفذ مؤقت؛ لا ينشئ حسابات اختبار في قاعدة التطوير.

## اختبار يدوي وإرجاع التغييرات

1. احتفظ بالخوادم القائمة. لتحميل backend الجديد أوقف خادم VOIC من طرفيته أنت ثم نفذ
   `pnpm.cmd build` و`pnpm.cmd start` من backend؛ frontend يستخدم `pnpm.cmd dev` من frontend.
   الافتراضي http://localhost:8443 وreadiness http://localhost:3000/api/v1/health/ready.
   لا تشغل نسخة ثانية على المنفذ نفسه. إعداد التطوير الخاص بالكتابة مطلوب كما سبق.
2. لا توجد حسابات موظفين افتراضية. أداة `node scripts/provision-local-staff.mjs` تفاعلية
   لإنشاء/ترقية حساب محدد صراحة، وتقبل `administrator,sales,content_editor`؛ ابنِ
   `.tmp/security-build` أولًا وفق [دليل الموظفين](staff-inquiries.md). كلمة المرور محليًا فقط.
   استخدم ملفي متصفح منفصلين للمدير والمحرر؛ العميل/المبيعات يجب أن يرفضا شاشة المحتوى.
3. افتح `/staff/products` ثم `/staff/products/ghazal`؛ أضف `?lang=en` للإنجليزية. دوّن الوصف
   الأصلي قبل تعديل تجريبي بسيط. احفظ مسودة: صفحة `/products/ghazal` تبقى على النص الأصلي.
   عاين، ثم اطلب مراجعة. المدير يقارن النسخة ويؤكد النشر؛ عند إعادة الجلب يظهر النص الجديد.
   لا تحدد اعتماد الإنتاج لتجربة محلية. أعد النص الأصلي بالحفظ والمراجعة والنشر لإرجاعه.
4. افتح السجل نفسه بجلستين؛ احفظ تعديلًا في الأولى ثم حاول من الثانية. يظهر التعارض ويبقى
   نصك؛ «تحديث ومقارنة» يعرض نسخة الخادم ولا يستبدل مدخلك إلا بزر واضح.
5. `/staff/categories`, `/staff/uses`, `/staff/recipes`, `/staff/content`, `/staff/media`
   هي الوحدات الحقيقية. سجل صفحة `shared` يغير الاتصال المشترك بعد المراجعة والنشر فقط؛
   دوّن القيمة الأصلية وأعد نشرها بعد الاختبار. الرئيسية تحتفظ بالأربع featured وترتيبها ما
   لم يعدل المدير القائمة صراحة. لا تغير الهوية الثابتة أو تدّع حقائق تجارية أو قانونية جديدة.
6. ارفع PNG صغيرًا بنصي alt عربي/إنجليزي، عاينه واختره لمسودة. لا تنشر صورة تجريبية على
   منتج حقيقي إلا إذا أردت هذا التغيير. الاستخدام في مراجعة محفوظة يمنع الحذف حتى بعد
   الرجوع لصورة الأصل، لأن التاريخ محفوظ. اختبار حذف نظيف: ارفع صورة ثانية غير مستخدمة ثم
   احذفها من المكتبة. لا تحذف الملفات يدويًا ولا تعدّل الأصول الأصلية.
7. `/recipes` يعرض الأربع، وروابط المنتجات والصور الأصلية محفوظة. جرّب البحث والمرشح،
   تغيير كمية المكونات، checklist والطباعة، وأعد تحميل الرابط المباشر. فشل API يجب أن يظهر
   خطأ مع إعادة محاولة. صفحات `/about,/business,/contact,/privacy` والرأس والتذييل تقرأ المنشور.
8. أنشئ مسودة استفسار بـAl-Ghazal: اعرض 1 لتر و2 كغم وخيار المناقشة الصريح؛ لا يختار
   النظام المناقشة نيابة عن المستخدم عند وجود عبوات. المنتج ذو الحجم المجهول يحتفظ بخيار
   المناقشة دون اختراع عبوة. أغلق استفسارًا من جلسة الموظف مع نص غير مرسل في جلسة ثانية:
   يظل النص ظاهرًا قابلًا للنسخ، وتختفي أفعال الإرسال والمراجعة التي لم تعد ممكنة.
9. اختبر العربية/الإنجليزية وعرض 390px وTab؛ الأزرار متجاورة ومتجاوبة، التركيز ظاهر، ولا
   pagination لصفحة واحدة، والتواريخ والمراجع معزولة الاتجاه والتذييل دون قص أفقي.
